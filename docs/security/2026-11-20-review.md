## Backend and database assessment

Existing SQL bindings, field allowlists, exact BigInt money calculations, transactions/locking, immutable receipt/history triggers, no-store responses, Origin/Host checks and live user/session/MFA assurance checks remain active. No raw HTML/eval sink was found in `src`; the one `sql.raw` use is a fixed history JSON-schema constant, not request input. Equal approved business-user access is preserved; no new business or superadmin role was introduced.

The isolated security server uses a **separate restricted MySQL runtime credential**. Its operator credential can migrate/provision the synthetic schema; that credential and a usable operator capability are not supplied to the web server. Explicit empty operator environment values prevent the CLI env loader from importing an owner operator key into that test server.

Test grants: SELECT on users/account-control; column-only UPDATE on users.auth_version/updated_at for the existing MFA replacement flow; SELECT/INSERT on audit, entity versions and receipt versions; SELECT/INSERT/UPDATE on operational/auth tables; DELETE only on expired passkey challenges. Actual client/project/contract/payment/receipt creation, idempotent retry and exports work under these grants. DDL, cross-schema reads, history UPDATE/DELETE and account-status changes are denied by MySQL itself.

**These restricted grants were applied only to a fresh task-owned test user/schema.** The owner's manual-test/runtime database credentials and permissions were not modified. Production must adopt and verify the reviewed privilege separation in its own approved infrastructure process; this report does not claim that an unexamined real database already has these grants.

The real schema is compared with the declared tables, columns, InnoDB engines, DECIMAL precision, indexes/uniqueness, foreign keys, enforced CHECK constraints and all thirteen original trigger identities. No financial trigger or historical migration was changed.

An existing metadata-test bug lowercased enum literal values, incorrectly treating the valid passkey `singleDevice`/`multiDevice` schema as inconsistent. The inspection helper now normalizes SQL keywords while preserving literal case, with a regression test. The application schema was not changed to satisfy the test. Actual inspection: **25 tables, 51 foreign keys, 106 indexes, 49 enforced checks, 13 original triggers**.

## Attack and regression evidence

The reproducible security lab uses MySQL 8.4 on loopback 3307 and a temporary production-mode server on port 3000. It refuses to replace an existing server, creates random schema/users, validates the MySQL server UUID and scopes cleanup to those exact resources. Synthetic accounts complete real password/TOTP enrollment; no production authentication bypass is added. Edge uses an isolated browser context and blocks external requests.

- Every current business API pattern/method, expanded reference families and representative private pages: **372 denial requests** across anonymous, malformed, pre-MFA-as-session, expired, revoked and disabled credentials. No private canary is returned. Private APIs retain no-store.
- Foreign Origin/null Origin CSRF, protected-field injection, MIME confusion, oversized JSON, parameterized SQL-injection searches and forged proxy/RSC/nonce headers. Patched Next first normalizes RSC requests to its same-origin `_rsc` URL; the normalized API still denies access.
- Real original PDF, report PDF/XLSX and complete ZIP under restricted grants. Checked passwords/tokens/digests, TOTP seed, recovery codes, encryption keys and factor ciphertext are absent from exported JSON/CSV. The original issued PDF checksum matches its archived bytes.
- Stored/reflected HTML payloads remain text in real Edge. Parser-injected private scripts and public/private event handlers do not run. Public mobile navigation still works. Secure/HttpOnly/SameSite session cookies, password-before-recovery, logout, live deactivation, forged operator denial and no checked secrets in browser storage are exercised.
- Redacted scans cover current Git tracked/untracked nonignored source, public files, production browser bundles, tracing paths and security-server logs. These are known-sentinel/credential-format scans, not exhaustive historical-blob or entropy analysis.

Evidence and final command outcomes are stored in [2026-11-20-verification.json](2026-11-20-verification.json). The original full historical database/HTTP/restore suites are not all rerun by this scoped review; no claim of complete ASVS recertification or independent penetration testing is made.

Final unit/domain suite: **100 PASS**, zero failures/skips. Business/passkey regression: **51 real Edge/MySQL scenarios** (workspace 8, dashboard 5, management 9, polish 10, passkeys 19). TypeScript, lint, production build, Drizzle configuration/check and migration preservation checks pass. Production build completes without the previous vulnerable-Next reminder. The synthetic passkey tests use virtual CTAP2 hardware; physical biometric/PIN behavior is not claimed.

## Remaining security limits and release blockers

- Security cannot be guaranteed at 100%. Independent review and continued patching/monitoring remain necessary.
- Public pages remain static and retain the documented inline Next bootstrap exception; styles remain inline-compatible. Public event handlers are now blocked, but a strict global script policy is **not complete**. Existing ASVS V3.4.3 remains FAIL; this change does not silently relabel the historical matrix as conformant. No public untrusted HTML sink was found or introduced.
- Production hosting, HTTPS/reverse-proxy normalization, HSTS, secure-cookie delivery, network exposure, database grants/TLS, runtime secret distribution, private storage ACLs and encrypted/offsite backup operations are not certified by local tests. Keep the existing NO-GO release gate until these are independently verified.
- Current database configuration remains explicitly loopback/disposable-only. This package does not turn a development database into a production environment.
- Session idle-timeout policy, export step-up/quotas and operational alert routing remain owner/security decisions. Login/session lifetimes and business permissions were intentionally preserved.
- Stolen valid sessions, TOTP phishing, compromised browser/device/host, volumetric denial of service and authorized users exporting company data remain residual threats; the tested controls do not eliminate them.
